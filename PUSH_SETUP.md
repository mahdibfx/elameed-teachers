# Push notifications — state

**App side: done.** Firebase project `elameed-system` (number 354074649082), Android app
`com.elameed.teachers` ("Elameed Teachers", app id `1:354074649082:android:b17e8086a2736c1cb9c443`).

- `android/app/google-services.json` — downloaded from the project, committed (it is not a secret).
- `lib/firebase_options.dart` — generated by `flutterfire configure`.
- Gradle: `com.google.gms.google-services` is applied in `android/settings.gradle.kts` and
  `android/app/build.gradle.kts`.
- `lib/services/push_service.dart` asks permission, sends the FCM token to `POST /devices` after
  login, removes it on logout, and on `SESSION_CHANGED` / `SESSIONS_CHANGED` / `SESSION_REMINDER`
  reloads the sessions and rebuilds the local reminders.

## Left on the backend / office side

1. Firebase → *Project settings → Service accounts → Generate new private key*, then set that whole
   JSON as **`FCM_SERVICE_ACCOUNT_JSON`** on Render. Until it is set, the server skips every push.
   It is a password: never commit it.
2. iPhone would additionally need an Apple Developer account and an APNs key. This app is Android
   only, so nothing to do.

## Testing it

1. `flutter run` on the phone, log in as the test teacher → Android asks for notification
   permission → the app calls `POST /devices`.
2. In the office dashboard, move or cancel a future session of group 310 → the phone shows
   "Session changed" / "Session cancelled" within seconds.
3. 24 hours before a session, "Upcoming session" arrives with the reminder email.

The first build after this change is a clean one: `flutter clean && flutter run`
(the package name changed from `com.teachers.teachers_app`, so uninstall the old build first).
